# ComfyUI in the shared screen-production pipeline

Research date: 2026-10-30. Read-only source, installed-file, PNG-metadata and already-running local API inspection; no generation, service launch, downloads, or changes to existing plans/code. Python inspections used the activated project venv. This report distinguishes historical render evidence, current registration/file presence, and recommendations.

## 1. What should ComfyUI own, and what is actually available?

### Takeaway

Use this fork as the local still-image/preparation workstation: cheap previs, visual alternatives, reference-conditioned local experiments, resizing, masks and selective refinement. Keep the user's preferred high-quality video work with Kling, character/first–end-frame authority with Higgsfield SoulV2, and phone-reference complex action with Genjutsu/motion control; these are ownership recommendations, not newly verified claims about those providers.

### Inferences

- **Recommended ownership:** ComfyUI owns inexpensive draft stills, composition tests, local variations, nondestructive size/format preparation, supplied masks, and optionally validated SAM/RealESRGAN operations. SoulV2-approved character references remain the authority; Klein is a local continuity experiment/previs aid. Final hero first/end frames should remain in the user's chosen Higgsfield approval flow unless the user explicitly selects a local result.
- Use plain resize/model upscale when preserving an approved identity matters; review any img2img refine as a new candidate because it can change faces, wardrobe or scene details.
- Keep phone motion references as actual reference video assets. Do not make depth/pose extraction a mandatory precondition for Genjutsu when the local automatic extractors are not established as ready.
- ComfyUI can preserve, trim/prepare or organize supplied voice reference media through local audio tooling, but this report establishes neither ready cloning weights nor a production voice synthesis pipeline. Reserve character voice identity in the shared manifest now; choose synthesis only after a separately scoped readiness check.

### Gaps

- No new render, quality/identity comparison, learned-upscale test, SAM run, pose/depth extraction, or voice synthesis was authorized. Node registration plus weight presence is deliberately weaker than production readiness.
- Other external model locations or private caches were not exhaustively searched. Missing means absent from the model directories/cache inspected and not evidenced in this pipeline, not proof that no copy exists anywhere on the computer.

## 2. Which identities and naming contracts must converge?

### Takeaway

Adopt OpenReel's existing production identity for working shot/take/entity assets and send exact reserved output paths to the existing worker. Keep Argon's asset IDs/provider aliases as explicit mappings; neither renaming ComfyUI's legacy sheet IDs nor assuming an existing unified event identity will work.

### Cited Findings

- **OpenReel working names are already shared contracts:** project codes normalize to 2–6 uppercase alphanumerics; scene `S012`; shot `HSTL_S012_SH03`; take `HSTL_S012_SH03_kl-v3o_T02.mp4`; entity `HSTL-CHR-MARA`. Entity kinds are `CHR | LOC | PRP | VOX`. `elementName` truncates the whole name to 32 characters. Parser accepts exactly three scene digits/two shot and take digits, lowercase model tags, and an optional extension. [Source: `/mnt/data/Projects_SSD/openreel-video/packages/core/src/script/naming.ts:14-99`](file:///mnt/data/Projects_SSD/openreel-video/packages/core/src/script/naming.ts#L14-L99)
- Existing fields cover entity code, description, refs, Kling `elementId/type`, Higgsfield `elementId/soulId`; shots carry `sceneCode`, dialogue, entity codes and image/video/audio refs; takes carry `generationId`, target, filename/localPath, review and speech. There is **no event identity or voice-provider-ID field in these inspected interfaces**. `ProductionManifest.version` is 1 and may retain the original Fountain script. [Source: `/mnt/data/Projects_SSD/openreel-video/packages/core/src/script/production.ts:126-222`](file:///mnt/data/Projects_SSD/openreel-video/packages/core/src/script/production.ts#L126-L222)

### Inferences

- Minimal working examples: `shots/S001/TH_S001_SH01_cf-zit_T03.png`, `shots/S001/TH_S001_SH01_hf-soul2_T04.png`, `shots/S001/TH_S001_SH01_kl-v4_T05.mp4`; character references `refs/CHR/TH-CHR-MARA/TH-CHR-MARA_01.png`; location `refs/LOC/TH-LOC-ALLEY/TH-LOC-ALLEY_01.png`. Preserve existing model tags; choose and register a Klein tag on the OpenReel side rather than inventing one in the Comfy worker.
- `VOX` already supplies a namespace for voices; use it instead of a new unrelated voice naming system. A proposed `refs/VOX/TH-VOX-MARA/TH-VOX-MARA_01.wav` is a consistent naming extension, **not evidence of an implemented audio-reference registration workflow**. Link character identity to voice identity explicitly rather than relying on matching display labels.
- Keep final shot/take filenames parseable. Store first/end-frame role, event/beat association, character angle, phone-motion source, source script revision, and any provider voice ID as manifest metadata or a reviewed boundary mapping—not as arbitrary inserted filename tokens that break `parseProductionName`.
- A minimal future story mapping should connect a script revision and stable event/beat identity to existing scene/shot IDs and entity codes. Do not equate `cf-*` jobs, Comfy `prompt_id`, or timestamped filenames with story events. The absence of event fields is a real gap to resolve at OpenReel's production-contract layer, outside Comfy core.
- If Argon remains part of the production path, maintain an explicit association between OpenReel shot/entity IDs and Argon shot/asset/provider identities. Do not rename all masters or presume similarly named shots are automatically joined. Prefer one operational manifest owner for new work.

### Gaps

- No shared event schema, persistent screenplay revision ID, shot-to-event relationship, or character-to-provider-voice mapping was found in the inspected production interfaces. These must be identified in the coordinator's adjacent research or described as small additive work, not claimed as shipped.
- OpenReel's 32-character entity truncation can collapse long similar names; review codes for uniqueness. Existing IDs and takes should not be renumbered merely to make a newer outline prettier.

## 3. What existing integration, provenance and plans should the final strategy build on?

### Takeaway

Reuse the folder-job worker and manual Argon handoff. Reconcile documented plans against current source before declaring end-to-end availability: the Comfy worker is implemented, but the inspected OpenReel main checkout does not yet contain the planned producer module or Comfy targets.

### Cited Findings

- **Official local API:** ComfyUI documents API-format `/prompt` submission with `client_id`, execution monitoring, `/history/{prompt_id}`, and image retrieval via `/view`. Both local runners submit with a random client ID and use history polling; worker timeout is 1800 seconds. Current official docs were retrieved with `bunx ctx7 library ComfyUI ...` followed by `bunx ctx7 docs /comfy-org/docs ...`. [Official API examples](https://github.com/comfy-org/docs/blob/main/development/comfyui-server/api-examples.mdx) · [Official routes](https://github.com/comfy-org/docs/blob/main/development/comfyui-server/comms_routes.mdx) · [Local implementation](file:///mnt/data/Projects_SSD/ComfyUI/studio/worker.py#L165-L191)
- **Queue semantics:** worker polls every 3 seconds, oldest job first, skips any job with a status file, processes sequentially, marks startup `running` jobs `failed: interrupted`, atomically replaces status and output files, refuses existing outputs, and preserves earlier successful outputs on partial failure. It has no cross-application GPU scheduler. [Source: `/mnt/data/Projects_SSD/ComfyUI/studio/worker.py:26-29,130-162,231-281`](file:///mnt/data/Projects_SSD/ComfyUI/studio/worker.py#L130-L281)
