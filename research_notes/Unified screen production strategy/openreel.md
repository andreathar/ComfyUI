## 2. What editing, ingest, sound, finishing and interchange capabilities are actually supported?

### Takeaway
The fork has substantial native local editing, sound mixing, captions and grading. **Voice generation is an in-editor ElevenLabs integration, not a local/native speech model; no native voice-clone creation or visual lip-sync implementation was verified.** Browser codec support and the very limited SHOTS-only EDL are major finishing boundaries.

## 3. What canonical provider handoff contract preserves shots, voices, sync and provenance?

### Takeaway
Keep the fork's existing shot/take/entity naming exactly. Add event semantics, immutable provider payloads, voice mappings and technical metadata in a **separate recommended handoff record**; the present production schema does not store all of them. Choose delivery frame rate early but preserve the original provider/camera file and its actual fps.

### Cited Findings
- Existing names: entity `<PROJ>-<CHR|LOC|PRP|VOX>-<SLUG>` max 32 chars; shot `<PROJ>_S###_SH##`; take `<shot>_<modeltag>_T##.<ext>`; HF folder `<PROJ>/S###/SH##`. Use entity code as cross-provider element name and generation ID as the remote-to-local link. `/mnt/data/Projects_SSD/openreel-video/docs/film-production.md:175-187`; `/mnt/data/Projects_SSD/openreel-video/packages/core/src/script/naming.ts:14-16,37-70`. [Canonical names](file:///mnt/data/Projects_SSD/openreel-video/packages/core/src/script/naming.ts#L37).
