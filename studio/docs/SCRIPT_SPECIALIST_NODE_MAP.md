# Studio production node map

Use this to make a task plan, not to configure ComfyUI. A frozen API graph is the authority on execution; this catalog describes the checked Rainy Street Master graph (`user/master_studio/takes/DEMO_S001_SH01/tk001/prompt.json`, SHA-256 `cad10ff7c6b9f10b88c344aeff7fbcf466d2b64a9c7d809c7edf24fe0a2fb622`). Do not apply that pilot’s settings to another project without checking its own recipe and graph. Canvas titles, inactive branches, and a loaded preset are not execution evidence.

## Plan each handoff

| Stage | Inputs and parameters to specify | Output → next owner; completion gate |
| --- | --- | --- |
| Story analysis | Exact excerpt, scene/location IDs, identity, wardrobe, props, time/light, dialogue and continuity decisions | Reviewed short shots → Storyboard; distinguish sourced facts from suggestions. |
| Reference bank | Role, entity/outfit and shot IDs; exact current asset ID/source version and status; if missing, required viewpoint/framing, not a guessed filename | Reviewed role assignments → Asset Library / Storyboard. Preserve originals; approval is separate from source selection. |
| Stills and endpoints | Goal, model/recipe, aspect/dimensions, seed and needed roles in order; start only by default, end target only if the result needs it | Decoded candidate and Brain receipt → human review. Use the selected start when the compatible end-frame adapter requires it. |
| Build the shot | Action, framing, camera, duration/FPS, audio and Cut/Continue; Builder text and state; exact picture/video/audio bindings and order, optional LoRA/RefMod choice | Editable Builder draft → evaluated CPU Reference Map, then frozen take. Save to the committed library source when the shot is resolver-driven. |
| Encode and sample | Effective UNet/CLIP/VAEs; input mode, dimensions/duration, fps, reference size/fps and token controls; seed, flow shifts, sampler, scheduler, steps, denoise | Text Encode conditioning/latent → Context → sampler. Frozen equality and actual encoder bindings are distinct checks. |
| Decode and review | Delivered frames, resolution, FPS/audio intent, isolated Hub/output destination; Brain enabled with run label; permission to submit | Suite media, review video and Brain receipt → reconcile exact prompt/history, decode and hash. Human chooses take and continuity tail separately. |

For every task return: **ID → prerequisites → node/tool → input references + parameters → output → completion check/approver**. Mark each parameter `recorded`, `proposed` or `needs confirmation`. If a requested route is not mapped below, read the selected frozen API prompt in the take folder and the corresponding guide, or ask for the graph export. Never infer a missing connection or value from a node’s name.

The checked snapshot used `16:9 (Widescreen)`, `0.2` megapixels and multiple `32`, `sa_solver` + `beta`, and denoise `1`. Text Encode used reference FPS `24`, size `match`, `stack_pictures=up to N`, `stack_pictures_n=4`, `max_total_tokens=0`. The cap rejects expensive RefMods, not ordinary media; the presentation count does not remove diffusion latents. Use the project’s actual values when available. Ref2VA takes ordinary/derived references; FL2VA needs composed endpoint frames and a separately verified graph, not a silent substitution into Ref2VA.

## Other preparation and delivery routes

- **Storyboard workspace**: Analyze story → review proposal and create project → edit and save shot plan → prepare role references → describe and review shot frame candidates → export or hand off accepted frames. Read `MASTER_MOVIE_STUDIO_GUIDE.md` and the project’s `production.json`, `assets.json`, `bindings.json` and `storyboard.json`; use a separate review for dialogue and multi-scene material.
- **Entity stills**: `studio/shot.py`/`studio/templates/z-image-t2i.json` for text-only candidates. Chain: `UNETLoader`, `CLIPLoader`, `VAELoader`, `ModelSamplingAuraFlow`, `CLIPTextEncode`, `ConditioningZeroOut`, `EmptySD3LatentImage`, `KSampler`, `VAEDecode`, `SaveImage`; `--brain` adds `WorkflowMonitorBrain`. Use the selected still preset’s dimensions, steps, CFG, sampler, scheduler and seed; keep candidate and approved asset separate.
- **Storyboard endpoint stills**: the local Klein compiler (`studio/still_recipe.py`, when the installed workspace supports it) uses the `flux2-t2i` template with `UNETLoader` plus `CLIPLoader`, `VAELoader`, `CLIPTextEncode`, `ConditioningZeroOut`, `CFGGuider`, `KSamplerSelect`, `Flux2Scheduler`, `EmptyFlux2LatentImage`, `RandomNoise`, `SamplerCustomAdvanced`, `VAEDecode`, `SaveImage`. For each staged input: `StudioStoryboardReference` checks filename/hash → `ImageScaleToTotalPixels` → `VAEEncode` → two `ReferenceLatent` nodes for the guider's positive and negative conditioning. The compiler sets about 0.5 MP, four steps, CFG 1, Euler, and a supplied seed. `WorkflowMonitorBrain` records the run. Check actual graph and creative approval separately.
- **Automated silent cut bundle**: `H3_LOOP_RUN.md` covers `h3_loop` bundle → verified Context Loop graph → preflight → one prompt ID → native manifest and decoded ordered clips. `DynamicLoadTextFileNode` reads the bundle; two `DynamicScriptNode`s compile the plan and select per-shot references. `MiniMaxH3GenerationProfile` / `MiniMaxH3ChainPlanModern` define policy; `MiniMaxH3ChainLoopStart` / `MiniMaxH3ChainCurrent` feed each shot to the H3 encode/sample/decode nodes. `MiniMaxH3LoopTrim` / `MiniMaxH3ChainSegmentSave` write separate segments; `MiniMaxH3ChainLoopEnd` advances the loop and `MiniMaxH3ChainAssemble` emits the checked final output. Separate from the Master single-take route. Do not assume continuity, dialogue, intercut/edit transitions or other graph topology is qualified. Verify `between_scene_cleanup` with the actual graph and hardware before queuing.
- **Media/log review**: cross-check Brain `run.json` with exact Master/Suite take and media hashes; visual judgment must come from a reviewer or a verified visual tool. A reference generation receipt is not a video render.
