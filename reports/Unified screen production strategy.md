## 1. Give each platform a narrow production responsibility

The control layer and the generator have different jobs. For new OpenReel work, OpenReel should own the script breakdown, canonical shot/take names, selection and timeline; local production folders retain durable assets and provenance. For the existing film, the Movies_Projects board, decisions, script and producer remain authoritative until an explicit handoff is adopted. OpenReel is an editorial destination and proposed operational desk, not permission to replace that board or create a second approval authority. Argon's existing shots and asset IDs also remain separate mappings if it stays in the path. ## 2. Converge on story identity without breaking existing names

**Existing naming wins.** Preserve OpenReel's `<PROJ>_S###_SH##_<modeltag>_T##.<ext>`, its `<PROJ>-<CHR|LOC|PRP|VOX>-<SLUG>` entity names, and all existing film IDs such as `G-P04`, `G-L04`, `G-ID`, `G-TABLE`, `G-ERA`, `G-IN` and `G-OUT`. The current parser requires a 2–6-character uppercase alphanumeric project code, exactly three scene digits, two shot/take digits and a lowercase alphanumeric/hyphen model tag. Inserting `_EV...` into take filenames would break recognition. Entity names are truncated to 32 characters, requiring a uniqueness check. ([Exact parser and helpers](file:///mnt/data/Projects_SSD/openreel-video/packages/core/src/script/naming.ts#L14-L99); [Existing Galileo registry](file:///mnt/data/Projects_SSD/Movies_Projects/projects/andre-time-travel/05_storyboard/source/production-plan.json#L431-L575))

### PROPOSED: one small crosswalk and one immutable request record per take

Use an explicit record under the production folder's `handoff/`, outside auto-scanned shot folders. This is a **proposed convention, not an implemented schema or a new database**. The existing OpenReel manifest stores entities, refs, prompts, generation IDs, take paths, review and speech, but not all event, voice-provider, hash, timing or provenance fields below. Do not assume arbitrary additions survive its parsing/rebuild. ([Current manifest](file:///mnt/data/Projects_SSD/openreel-video/packages/core/src/script/production.ts#L126-L222); [Sidecar placement warning](file:///mnt/data/Projects_SSD/openreel-video/docs/superpowers/specs/2026-10-30-comfyui-jobs-design.md#L110-L117))

| Record | Minimal proposed fields and rule |
|---|---|
| Story and revision | Existing project slug; frozen original screenplay plus revision ID/hash; scene ID and original heading/alias. Never replace the original draft with only an editor rebuild |
| Stable event | Event ID, label, source script/line span, intention, trigger, before/after state, display order. Insertion gets a new ID; split/merge retains `derivedFrom`; changing order does not renumber existing events |
| Shot | Existing authoritative shot ID plus OpenReel/Argon/Comfy aliases; event IDs, line IDs, continuity-in/out, required coverage. One event can span shots; one shot can cover several events |
| Entity and version | Existing CHR/LOC/PRP/VOX codes and aliases; visual identity, wardrobe, expression, location/light state and voice versions remain separate |
| Asset/reference | Stable asset ID, revision, original local path, SHA256, source kind, technical metadata, approved-use scope; explicit role: identity, wardrobe, location, prop, look, start, end, motion, camera, voice identity, exact dialogue or guide |
| Provider binding | Provider **and surface**, model/mode, opaque Element/Soul/voice/upload IDs, reference order, request slot and actual prompt token; schema date. Friendly names do not bind media |
| Request/take | Existing canonical take filename/ID; exact prompt and parameters; prompt revision; source asset hashes; seed when supported; provider job/output ID; timestamp; requested versus actual media settings; cost basis/receipt; original and derived paths |
| Audio/sync | Stable line ID, edition/language, voice version, audio take/hash, text/pronunciation revision, sample rate, sample offset and milliseconds, word timings, picture in/out frames and rational FPS, retiming and sync-parent IDs |
| Acceptance/invalidation | Candidate/reviewed/approved-for-use/rejected/superseded; reviewer, evidence, exact hash/version and permitted use. Changed dependencies mark affected descendants for review, not automatic deletion or rerender |

Keep take allocation monotonic within the shot and retain rejected/failed records; do not overwrite an approved take to retry. Provider task IDs, Comfy `prompt_id` and `cf-*` job IDs are execution identities, not story events. Download successful provider results into local canonical paths promptly: Kling CLI documentation reports result-URL expiry of 24 hours, while REST describes 30-day result retention; these are different lifetimes. ([OpenReel handoff proposal](../research_notes/Unified%20screen%20production%20strategy/openreel.md#L68-L90); [Kling persistence evidence](../research_notes/Unified%20screen%20production%20strategy/kling.md#L169-L183); [Kling REST](https://kling.ai/document-api/api/video/4-0/video-omni.md))

**Invalidation follows actual dependencies.** A script-line change affects its translations, speech takes, timing and visible-speech derivatives; an unchanged offscreen picture need not be regenerated. A voice change affects that character's audio and sync, not every location plate. A wardrobe/location revision affects only shots using it. A crop, generative repair or lip-sync derivative receives a new asset revision and its own review because the approved source does not guarantee the derivative. Approved old bytes remain available for comparison and recovery.

## 3. Translate one shot brief into different provider contracts

The common object is **intent plus bound assets**, not identical literal prompt text. Write a human-readable brief rooted in the frozen script, causal event and production nuances, then compile only the fields the chosen surface supports. Never discard a required reference silently, paste provider UUIDs into another provider, or assume a textual reference label uploads/binds the corresponding file.

```text
SOURCE: project, script revision/hash, scene, event(s), existing shot, line IDs
PURPOSE: what changes emotionally; triggering line/action; why this coverage exists
CONTINUITY: character/voice versions, wardrobe, props, location, table/seat/axis
BEGIN: body/hands/props, screen position, gaze, camera and light before the action
ACTION: observable ordered beats with relative timing; performer-to-character mapping
END: final body/prop/camera state and the next cut's continuity requirement
CAMERA/LOOK: framing, lens intention, viewpoint, movement, light, palette
REFERENCES: ordered files + hash + role + what to preserve and what not to copy
AUDIO: exact line, language, emotion, pronunciation, guide/final/offscreen intention
TIMING: measured audio window, pauses, handles, requested duration/aspect
REVIEW: identity, event completion, geometry, prohibited reveals, sync and technical QC
```

### Phone motion SOP: capture the action and camera separately in the brief

The following is **production guidance**, except for explicitly sourced model limits. The phone take is a performance asset, not just inspiration. Its brief should identify who moves, which hand touches which prop, what triggers the movement, whether the camera itself moves, and which parts of the original must not transfer into the result.

| Stage | Practical procedure | Acceptance / platform distinction |
|---|---|---|
| Prepare | Choose the exact event, final/guide audio window, beginning/end states, orientation and intended coverage. Assign performer A→character A; list wardrobe/set references separately | A generic “use this motion” prompt does not establish identity or per-actor binding |
| Stage | Match the appearance still's full/half-body framing; show hands/feet for full-body action; leave room around travel. Use steady light/focus and a simple readable background; minimize accidental occlusion | Recommendations, not universal codec or scene-complexity limits |
| Capture performance | Record one continuous readable action with anticipation, contact and follow-through, plus brief handles. Avoid cuts, unintended zooms and exposure jumps; retain the untouched original | For direct Motion Control, one largest visible subject is targeted; equal-sized subjects can fail selection |
| Capture camera | If only acting transfers, keep camera stable and explicitly exclude source camera/background. If the move is intentional, capture and label it; do not stabilize away the desired motion | Kling `motion_direction` follows video orientation/camera; `image_direction` keeps still orientation with prompt-guided camera |
| Select/prepare | Choose the shortest complete usable action; preserve native original, make trim/CFR/rotation/color derivatives only as needed; inspect aspect, duration, FPS, codec and audio | Genjutsu public limit: **4–30s**, up to **30 images**. Kling Motion Control nominal: **3–30s** motion-direction or **3–10s** image-direction |
| Map timeline | Record relative intervals for anticipation→action/contact→follow-through, exact contact point, source in/out, performer identity and dialogue cues; extract start/end stills | Timeline follows actual capture/approved audio; do not impose generic durations on every scene |
| Transfer/review | Select Genjutsu Motion Transfer for restaging retained motion/camera/timing; Object Swap for selective replacement; direct Kling for eligible single-person transfer | Test crossings/contact/prop handoffs before assigning a whole scene; no documented Genjutsu hard per-character binding guarantee |
